안녕하세요. 김용찬입니다. 검사 데이터를 넣으면 학습할 제품 묶음과 모델 예측의 혼합 비율을 비교하고, 선택 근거와 검증 결과를 보여 주는 Agent를 만들었습니다.

[2장 / 20초 / 누적 0:35] 모델 실험의 계획·비교·기록을 연결합니다
이 프로젝트에서 설정한 문제는 엔지니어가 학습할 제품 묶음과 모델, 혼합 비율을 직접 비교하고 근거를 정리해야 한다는 점입니다. 이를 계획부터 승인, 실행, 기록까지 연결했습니다. 스칼라에서 배운 모델도 후보에 넣었고 센서 사례로 설명하겠습니다.

[3장 / 25초 / 누적 1:00] 불량을 놓치지 않되, 정상 오판도 제한합니다
불량을 놓치지 않는 것이 목적이라 검출률을 우선합니다. 다만 전부 불량으로 찍는 것을 막기 위해 정상 오판률을 십오 퍼센트 이하로 제한합니다. 그 안에서 검출률이 높고, 같으면 F1이 높은 비율을 고릅니다. F1은 불량 검출과 불량 판정의 정확성을 함께 보는 보조 지표입니다.

[4장 / 15초 / 누적 1:15] ① 검사 데이터를 선택합니다
실제 앱 화면입니다. 제품 A부터 D의 합성 센서 천이백팔십 건을 선택합니다. 불량 정답은 이백한 건입니다. 직접 만든 예제로, 실제 공장 데이터는 아닙니다. 내 센서 CSV나 검사 이미지 ZIP을 등록하는 기능도 있습니다.

[5장 / 20초 / 누적 1:35] ② 비교 범위를 확인하고 승인합니다
먼저 개별 모델을 비교한 뒤 제품 묶음과 혼합 비율을 각각 검토합니다. 화면은 CatBoost 설정을 고정하고 열다섯 그룹 구성을 비교하는 계획입니다. 학습과 평가 데이터를 분리하고, 엔지니어가 비교 범위를 승인한 뒤에만 실행합니다.

[6장 / 35초 / 누적 2:10] ③ 제품 묶음 선택: ABC 공통 모델 + D 전용 모델
첫 실험은 학습 제품 묶음입니다. CatBoost 설정을 고정하고 제품을 나누는 열다섯 구성을 비교했습니다. Validation에서는 ABC 공통 모델과 D 전용 모델이 선택됐습니다. 하지만 Test 검출률은 칠십팔 점 일 퍼센트로 목표에 못 미쳐 적용을 보류합니다. Validation에서 좋다고 마지막 검증까지 좋지는 않았습니다.

[7장 / 30초 / 누적 2:40] ④ 선택 비율: CatBoost 90% + LightGBM 10%
다음은 학습 제품ABCD로 고정한 별도 비율 실험입니다. 다섯 퍼센트 간격과 균등 비율을 포함한 이백서른두 조합 중 CatBoost 구십, LightGBM 십 퍼센트가 선택됐습니다. 단일 모델과 검출률 백 퍼센트는 같지만 정상 오판이 스무 건에서 열아홉 건으로 줄고 F1도 개선됐습니다. 이 탐색 범위 안의 최선이라는 뜻입니다.

[8장 / 30초 / 누적 3:10] ⑤ 같은 검출률을 유지하며 정상 오판을 줄였습니다
비율을 고른 뒤 같은 Test에서 확인했습니다. 단일 CatBoost와 선택 조합은 둘 다 불량 서른두 개 중 서른 개를 찾았습니다. 정상 오판은 스물한 개에서 열아홉 개로 줄고 F1도 영 점 칠이삼에서 칠사일로 높아졌습니다. 이번 시연 목표는 충족했지만, 기존 Test를 다시 확인한 추가 탐색이므로 새로운 독립 데이터 검증이 필요합니다.

[9장 / 40초 / 누적 3:50] 역할을 나누고, 실행과 답변을 검증했습니다
LangGraph로 점검, 검색, 계획 역할을 연결하고 로컬 Qwen이 설명을 돕습니다. 수업에서 배운 BGE-M3로 문서를 벡터로 바꾸고 FAISS에서 관련 근거를 찾아 전달하는 RAG와 MCP 도구를 적용했습니다. 실험 엔진이 실제 학습과 지표를 계산합니다. LangSmith로 실행 경로를 확인했고 LLM으로 설명도 검사했습니다. 예제 여덟 개 중 여섯 개는 맞게 검사했지만 오판이 있어 숫자는 코드로 확인합니다.

[10장 / 25초 / 누적 4:15] 선택 근거와 검증 실패를 함께 남깁니다
성과는 제품 묶음과 혼합 비율의 선택 근거, 검증 실패까지 한 흐름에서 보여 준 점입니다. Validation에서 좋았던 그룹도 Test에서 실패할 수 있어 보류 판단이 필요했습니다. 합성 데이터와 작은 표본이 한계이며, 다음에는 현장 기준과 독립 데이터로 검증하겠습니다. 감사합니다.

[11장 / 질문용 부록] 비율을 섞기 전, 개별 모델 비교
초기 전체 제품 비교표입니다. AdaBoost는 F1이 더 높지만 이번에는 검출률을 먼저 보는 규칙을 따랐습니다. 초기 제품 조합 탐색의 CatBoost A+B+C와 이번 전체 제품 앙상블은 별도의 실험입니다.

[12장 / 질문용 부록] 공식 문서에서 비교 후보를 추가할 수 있습니다
외부 모델 탐색에는 공식 문서를 BGE-M3로 임베딩하고 FAISS에서 관련 문장을 찾아 로컬 Qwen에 전달하는 RAG를 씁니다. 5주차 실습과 같은 검색 구조이며 이 Windows에서는 Ollama로 임베딩을 실행합니다. FAISS 벡터와 출처를 로컬에 저장하며 별도 서버형 DB는 아닙니다. 학습 연결은 검토한 ExtraTrees와 GaussianNB 두 후보이고 임의 모델 코드를 자동 설치하지 않습니다.

[13장 / 질문용 부록] 선택이 최적이라는 말은 어디까지인가요?
최선이라는 말은 승인한 후보와 조건, Validation 범위 안에서의 선택을 뜻합니다. 제품 그룹 구성과 앙상블 비율은 별도 실험으로 비교했습니다. 둘을 모두 동시에 최적화했다고 주장하지 않습니다. 그룹 구성은 Test에서 목표 미달이었고 적용을 보류했습니다.

[14장 / 질문용 부록] LLM-as-a-Judge: 설명이 맞는지 LLM이 검사합니다
LLM-as-a-Judge는 설명이 맞는지 LLM에게 검사시키는 기능입니다. 실제로27개를 찾았는데30개라고 설명하면 틀렸다고 알려줘야 합니다. 실제 결과와 문장을 함께 주고 검사했고, 직접 만든 예제8개 중6개는 맞게 판단했습니다. 하지만30개라는 오류는 놓쳤습니다. 그래서 보조 검사로 쓰고 중요한 숫자는 코드로 확인합니다. 이 예시는 앙상블 추가 전의 실험 기록을 기준으로 검사했습니다.

질문 대비
Q. AdaBoost는 어디서 나온 모델인가요?
A. 15주차 반도체 발표자료 40~42쪽의 Adaboost Regression / Ada Boost 회귀 사례를 참고해 분류용 AdaBoostClassifier로 적용했습니다. 새 모델 탐색 RAG가 추가한 모델은 ExtraTrees와 GaussianNB입니다.

Q. 왜 F1이 더 높은 AdaBoost를 선택하지 않았나요?
A. 이번 실험은 사전에 정한 Recall 목표와 정상 오판 한도 충족을 먼저 보고, Recall 우선·동률이면 정상 오판이 낮은 후보를 골랐습니다. 다른 업무 목표라면 선택 규칙도 바뀔 수 있습니다.

Q. 6:2:2가 항상 최적인가요?
A. 수업 기준으로 정한 사전 고정 조건입니다. 모든 데이터에서 최적이라는 뜻은 아닙니다. 같은 lot·날짜 경계를 보존하고 Test를 보고 비율을 고르지 않습니다.

Q. 서로 다른 모델의 예측을 섞는 앙상블도 구현했나요?
A. 네. 각 모델의 불량 확률을 비율대로 곱해 더합니다. 단일 모델과 균등 비율도 포함해 비교했습니다. 현재 예제에서는 CatBoost90%와LightGBM10%가 선택됐습니다. Random Forest·부스팅 내부의 앙상블을 쓰는 것에서 한 단계 더 나아가, 서로 다른 모델 사이의 비율도 비교한 것입니다.

Q. 제품별로 따로 학습하는 것이 당연히 좋지 않나요?
A. 꼭 그렇지는 않습니다. 제품별로 나누면 특성은 맞추기 쉽지만 학습 데이터와 불량 표본도 줄어듭니다. 별도 합성 실험에서는 A는 전체 제품을 합친 모델이, C는 전용 모델이 Validation에서 더 높은 검출률을 보였습니다. 같은 제품의 같은 평가 행으로 비교해야 합니다.

Q. ABC용 모델과D용 모델로 나누는 것도 자동으로 비교하나요?
A. 네. 네 제품을 중복·누락 없이 나누는15개 구성을 모두 비교합니다. 같은 알고리즘과 설정을 고정하고 각 그룹의 모델을 Train으로 학습하며, 같은 Validation에서 구성을 고릅니다. 이번에는 ABC와D가 선택됐지만 Test에서는 목표 미달이라 적용을 보류했습니다. 앙상블 비율까지 동시에 최적화한 실험은 아닙니다.

Q. 왜 F1이 가장 높은 비율을 고르지 않나요?
A. 이번 목적은 불량을 놓치는 일을 줄이는 것입니다. 정상 오판률 한도 안에서 Recall을 먼저 높이고, Recall이 같을 때 F1으로 고릅니다. F1·Precision·오판률을 모두 함께 보여 줍니다. 실제 현장 기준은 업무 비용에 맞춰 정해야 합니다.

Q. 90대10이 정말 최적인가요?
A. 승인한 세 모델과5% 간격의 비율, Validation 데이터 안에서 정한 기준으로 가장 좋았습니다. 모든 모델과 모든 연속 비율에서의 최적이라는 뜻은 아닙니다. 선택 후 Test를 확인했지만 기존 Test의 추가 탐색이므로 새 독립 기간 검증이 필요합니다.

Q. 자동화와 Agent는 어떤 차이가 있나요?
A. 현재는 역할을 나눈 제한된 Agent 구조입니다. 근거를 검색해 설명하고 계획을 제안한 뒤 승인받은 도구로 모델을 비교합니다. 실제 수치·후보 순위·승인은 실험 엔진이 책임집니다. 자율 Supervisor나 무제한 모델 발굴을 구현했다고 주장하지 않습니다.

Q. LangSmith와 로컬 Qwen은 어떤 차이인가요?
A. Qwen은 노트북에서 설명용 응답을 만들고, LangSmith는 별도로 실행 경로를 기록합니다. Qwen을 로컬에서 돌려도 LangSmith 추적을 켜면 설정한 실행 기록은 외부로 전송됩니다. 지금은 공개·합성 데이터로 검증했습니다.

Q. 재학습이나 운영 감시도 발표하나요?
A. 추가 구현으로 보존했지만 이번 5분 발표는 데이터 점검·모델 비교·선택 근거에 집중합니다.

Q. LLM-as-a-Judge도 구현했나요?
A. 네. 실제 결과와 설명 문장을 LLM에 함께 주고 맞는 설명인지 검사했습니다. 직접 만든 예제8개 중6개는 맞게 검사했습니다. 예를 들어27개를 찾았는데30개라고 설명한 오류를 놓치기도 했습니다. 그래서 중요한 숫자는 코드로도 검사합니다.

Q. 결과 검토 Agent가 이미 Judge 아닌가요?
A. 결과 검토 Agent는 실험 결과를 설명하는 역할입니다. Judge는 그 설명이 실제 결과와 맞는지 다시 검사하는 역할입니다. 현재 평가에서는 실제 결과를 바탕으로 직접 만든 설명 예제들을 검사했습니다.

Windows 앱 실행: continued-project 폴더의 start.cmd를 더블클릭하고 http://localhost:8700을 엽니다.
새 환경은 예제 데이터 준비 → 계획 제안 → 승인·학습 순서입니다. 발표는 기록된 화면을 설명하므로 새 학습을 기다릴 필요가 없습니다.
