5분 발표 대본: 본문1~12장 / 13~17장은 질문용 부록
발화 목표260초 + 화면 전환20초 + 여유20초. 실제 리허설 측정값은 아닙니다.
새 학습을 기다리지 말고 준비된 실행 결과 화면을 설명합니다.

1장 · 10초 · 반도체 검사 모델
실험·관리 Agent
안녕하세요. SKALA 광주 2반 G045 김용찬입니다. 반도체 검사 모델을 비교하고, 이후 성능 점검과 재학습까지 돕는 Agent를 만들었습니다.

2장 · 15초 · 모델을 고를 때와 성능이 떨어졌을 때를 돕습니다
검사 모델을 만드는 엔지니어는 어떤 데이터를 함께 학습할지, 어떤 모델을 쓸지 반복해서 비교합니다. 만든 뒤에도 성능을 확인해야 합니다. 이 과정을 근거 확인, 승인, 실행으로 연결했습니다.

3장 · 40초 · 불량을 놓치지 않으면서, 정상도 지킵니다
불량을 정상으로 놓치면 다음 공정이나 고객에게 넘어가 품질 문제를 일으킬 수 있습니다. 그래서 실제 불량 중 얼마나 찾았는지인 Recall을 우선 봅니다. 하지만 모두 불량이라고 하면 Recall은 백 퍼센트여도 정상 제품까지 전부 잘못 잡습니다. 정상 오판은 불필요한 확인이나 제품 제외로 이어질 수 있어 제한합니다. 이번에는 정상 오판 한도 안에서 Recall을 먼저, 같으면 F1을 비교합니다. 구십 퍼센트와 십오 퍼센트는 교육용 목표입니다.

4장 · 10초 · ① 검사 데이터를 선택합니다
여러 센서 값으로 정상과 불량을 구분하는 합성 데이터 천이백팔십 건을 선택합니다. A부터 D는 가상 제품이며, 실제 공장 데이터는 아닙니다.

5장 · 30초 · ② 비교 범위를 확인하고 승인합니다
Agent가 빈값을 어떻게 채우고 숫자 크기를 맞출지 설명합니다. SVM처럼 값의 크기에 민감한 모델에는 Scaling을 씁니다. 데이터는 육십 퍼센트로 학습하고, 이십 퍼센트로 후보를 고릅니다. 마지막 이십 퍼센트는 선택한 모델의 최종 시험용으로 남깁니다. 계획을 승인하면 실제 학습합니다.

6장 · 30초 · ③ 제품 묶음 비교: ABC는 함께, D는 따로 학습
첫 실험은 제품을 모두 합칠지 나눌지 비교합니다. 같은 CatBoost로 열다섯 구성을 시험했더니, 후보를 고르는 데이터에서는 ABC를 함께, D는 따로 학습한 구성이 좋았습니다. 하지만 마지막 시험의 검출률은 칠십팔 점 일 퍼센트로 목표 미달이었습니다. 그래서 비교 후보로 선택했어도 적용은 보류합니다.

7장 · 20초 · ④ 선택 비율: CatBoost 90% + LightGBM 10%
앙상블은 여러 모델의 예측 점수를 섞는 방법입니다. 두 번째 실험에서는 제품 ABCD를 합쳐 학습한 세 모델의 비율 이백서른두 개를 비교했습니다. 후보 선택용 데이터에서 CatBoost 구십, LightGBM 십 퍼센트를 골랐습니다.

8장 · 20초 · ⑤ 같은 검출률을 유지하며 정상 오판을 줄였습니다
선택한 비율로 마지막 시험을 봤습니다. 단일 모델과 혼합 모델 모두 불량 서른두 개 중 서른 개를 찾았습니다. 정상 오판은 스물한 개에서 열아홉 개로 줄었습니다. 불량을 찾는 성능을 유지하면서 정상도 덜 잘못 잡은 사례입니다.

9장 · 20초 · ⑥ 새 정답 데이터로 기존 모델을 점검합니다
모델을 만든 뒤에는 새 데이터에서도 잘 찾는지 확인합니다. 여기서는 사람이 확인한 정답처럼 정상·불량이 표시된 별도 합성 데이터를 넣었습니다. 기존 모델을 그대로 점검하고 성능이 떨어지면 재학습 비교를 제안합니다. 표본이 부족하면 판단을 보류합니다.

10장 · 30초 · ⑦ 승인 후 재학습하고, 같은 Test에서 비교합니다
엔지니어가 승인하면 같은 CatBoost로 새 데이터를 다시 학습합니다. 같은 마지막 시험에서 불량 발견이 백육십일곱 개 중 마흔세 개에서 백쉰세 개로 늘었습니다. 정상 오판은 아흔여섯 개에서 일흔아홉 개로 줄었습니다. 재학습 후보를 저장하고, 운영 모델 교체는 엔지니어가 별도로 판단합니다.

11장 · 15초 · 역할을 나누고, 실행과 답변을 검증했습니다
설명과 계획은 언어모델이 돕고, 학습과 숫자 계산은 코드가 담당합니다. 역할 분리와 근거 검색, 도구 연결, 실행 추적을 적용했습니다. 테스트 쉰두 개와 설명 검사 결과도 남겼습니다.

12장 · 20초 · 선택 근거와 검증 실패를 함께 남깁니다
이 Agent는 모델 선택뿐 아니라 성능 점검과 승인 후 재학습까지 돕습니다. 좋은 점수만 보여 주기보다 선택 이유와 실패도 기록했습니다. 합성 데이터 결과이므로 실제 적용 전에는 새 생산 데이터와 현장 기준으로 다시 검증해야 합니다. 감사합니다.

질문 대비 (발표 본문에서는 읽지 않습니다):
- 불량을 Positive로 둡니다. 불량을 정상으로 놓침은 FN, 정상을 불량으로 오판은 FP입니다.
- Recall: 실제 불량 중 찾은 비율 = TP/(TP+FN).
- 정상 오판률: 실제 정상 중 불량으로 잘못 판정한 비율 = FP/(FP+TN).
- Precision: 불량이라고 잡은 것 중 진짜 불량의 비율 = TP/(TP+FP).
- F1: Precision과 Recall을 함께 보는 조화평균. 정상 오판률과 동일한 지표는 아닙니다.
- 모두 불량이라고 판정하면 Recall100%, 정상 오판률도100%입니다(정상·불량이 모두 있는 경우).
- 정상 오판이 곧바로 폐기를 뜻하지는 않습니다. 확인·보류·제외 등 후속 정책에 따라 영향이 달라집니다.
- 90%·15%·불량20개·Recall10%p 넘는 하락은 교육용 기준입니다. 회사 공통 기준은 아닙니다.
- Train=모델 학습, Validation=후보·비율 선택, Test=선택이 끝난 뒤 마지막 확인. 6:2:2를 고정했습니다.
- 공통 모델은 여러 제품을 함께 학습한 모델, 전용 모델은 특정 제품만 학습한 모델입니다.
- 현재 관리 기능은 정답이 있는 새 배치의 점검이며 상시 감시는 미구현입니다.
- 재학습 사례는 새 합성 배치이며 앞선 그룹·앙상블 사례와 데이터가 다릅니다.
- 같은 알고리즘을 새 Train으로 다시 학습하며 과거 파일을 자동 병합하지 않습니다.
- 운영 모델은 자동 교체하지 않으며 후보·버전·승인·비교 결과를 저장합니다.
