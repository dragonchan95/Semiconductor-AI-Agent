[1장] 반도체 검사 모델 관리 Agent

[2장] 불량 발견과 정상 제품 추가 검사
먼저 용어부터 쉽게 설명하겠습니다. 실제 불량 10개 중 8개를 찾으면 불량 발견 비율, 즉 Recall은 80퍼센트입니다. 실제 정상 100개 중 5개를 불량 의심으로 고르면 정상 추가검사 비율, 즉 FPR은 5퍼센트입니다. 화면의 허용 비율 15퍼센트는 정상 100개 중 최대 15개까지 추가 검사 대상으로 잘못 고르는 것을 허용한다는 뜻입니다. 이 장의 숫자는 설명용 예시입니다.

[3장] Agent와 엔지니어의 역할
Agent는 데이터를 점검하고 관련 정책을 검색한 뒤 비교할 실험 조건을 정합니다. 새 데이터에서 성능이 떨어지면 왜 재학습이 필요한지 수치로 제안하고 제품별 학습 계획을 준비합니다. 엔지니어가 계획을 승인해야 실제 학습을 시작합니다. 학습이 끝나면 후보 모델과 검증 결과를 저장합니다. 현장 운영 모델을 자동으로 교체하지는 않습니다.

[4장] 불량 28개 추가 발견, 정상 약 97개 추가 검사
스칼라와 반도체 자료의 Random Forest를 후보로 사용해 다시 비교했습니다. 측정 비율을 제품 천 개 상황으로 환산하고 불량100개,정상900개라고 가정했습니다. 기본 모델은 불량60개,선택 모델은88개를 찾습니다. 대신 정상 추가검사는 약5.4개에서102.4개로 늘어납니다. 불량28개를 더 찾는 대신 정상 약97개를 더 검사합니다. 미검출10만원,정상 추가검사천원 가정에서는 손실이 약270.3만원 줄어듭니다. 실제 이익 측정값은 아닙니다.

[5장] 재작업이 가능하다면 양품을 얼마나 회수할까
검사만으로 제조 수율은 자동으로 오르지 않습니다. 두 모델이 찾아낸 불량의20퍼센트를 재작업으로 정상화할 수 있다고 가정하면 기본 모델은12.0개,선택 모델은17.6개를 회수합니다. 재작업 후 양품 비율은91.20퍼센트에서91.76퍼센트가 되어0.56퍼센트포인트 차이가 납니다. 실제 결함이 재작업 가능한지는 확인하지 않았고,이 값은 시나리오입니다.

[6장] 공개 공정 데이터에서는 추천 보류
실제 공개 자료인 UCI SECOM도 사용했습니다. 최종 평가 264개 중 불량은 15개였습니다. 선택 모델은 불량을 더 찾았지만 정상 제품의 65.5퍼센트를 추가 검사 대상으로 골랐습니다. 허용 기준 15퍼센트를 크게 넘습니다. 따라서 Agent는 추천을 보류합니다. 좋은 숫자만 보여주는 대신 실제 데이터에서 실패한 이유도 보여주는 것이 이 프로젝트의 중요한 기능입니다.

[7장] 새 데이터에서 성능 저하를 판단
불량 발생 규칙을 바꾼 독립적인 합성 데이터를 넣었습니다. 기존 Random Forest 모델의 불량 발견 비율은 이전 평가에서88.0퍼센트였지만 새 배치 점검에서37.1퍼센트로 떨어졌습니다. 정상 추가검사 비율도23.9퍼센트로 기준을 넘었습니다. Agent는 이 수치로 재학습 필요라고 판단합니다. 판단은 개발 규칙이며 서로 다른 배치의 비교입니다.

[8장] 공통 모델과 제품별 전용 모델 비교
공통 모델1개와 제품 전용 모델4개를 승인 후 실제 학습했습니다. 같은 제품의 같은 평가 데이터를 사용해 방식을 비교합니다. 이번 결과에서는 A는 공통 모델,C는 전용 모델을 권고했습니다. C의 발견 비율과 추가검사 비율은 동률이어서 불량에 높은 점수를 주는 순위 지표 AP로 결정했습니다. B는 선택용 데이터 기준을,D는 최종 평가 기준을 넘어서 보류했습니다. 제품을 합치거나 나누는 방식이 항상 우수한 것은 아닙니다.

[예상 질문]
Q. 정상 오탐률 상한이 무엇인가요?
A. 정상 제품 100개 중 잘못 불량 의심으로 고르는 수를 제한하는 것입니다. 화면에서는 정상 제품 추가 검사 허용 비율이라고 표현했습니다.
Q. 정말 수율이 0.56%p 오르나요?
A. 실제 효과는 측정하지 않았습니다. 불량 10%, 검출률 유지, 검출 불량의 20% 재작업 성공이라는 가정에서 재작업 후 양품 비율 차이를 계산했습니다.
Q. 영업이익이 270만원 늘어난다는 뜻인가요?
A. 미검출과 정상 추가검사 단가만 넣은 손실 차이입니다. 재작업비, 설비비와 매출을 포함하지 않아 영업이익이라고 말할 수 없습니다.
Q. 새 모델이 기존 모델보다 무조건 좋나요?
A. 아닙니다. A는 공통,C는 전용 방식을 권고했고 B,D는 보류했습니다. 서로 다른 제품 지표끼리 우열을 정하는 결과도 아닙니다.
Q. 왜 AI Agent라고 부르나요?
A. 데이터를 점검하고 검색 근거와 규칙을 바탕으로 다음 실험을 제안하며, 승인 후 도구 실행과 결과 저장까지 연결합니다. 자유롭게 추론하는 LLM Agent는 아직 구현하지 않았습니다.
Q. 공정 조건별 수율 예측은 되나요?
A. 향후 확장입니다. 실제 공정 조건과 lot별 투입·양품 수량, 시간 및 장비 이력 데이터가 필요합니다. 이번에는 검사 모델 관리에 집중했습니다.
