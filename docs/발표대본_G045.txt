[1장] 반도체 불량 판정 모델 선택·재학습 Agent
안녕하세요. G045 김용찬입니다. 반도체 불량 판정에 어떤 모델을 사용할지, 성능이 떨어지면 언제 다시 학습할지를 도와주는 Agent를 만들었습니다. 엔지니어가 계획을 확인하고 승인하면 실제 학습을 실행합니다.

[2장] 엔지니어가 결정해야 할 세 가지
처음에는 여러 모델 중 하나를 골라야 합니다. 이후 공정이나 데이터가 바뀌면 기존 모델의 성능을 확인해야 하고, 제품 데이터를 합칠지도 결정해야 합니다. SK하이닉스의 공개 사례에서도 검사 AI의 성능 감시와 성능 저하 후 복구, 새로운 결함 학습이 운영 과제로 나옵니다. 이 프로젝트는 이 결정을 돕는 교육용 구현입니다.

[3장] Recall이 우선, Precision·F1도 함께 확인
여기서는 불량을 Positive로 정합니다. 중요한 오류는 실제 불량을 정상으로 놓치는 FN입니다. Recall은 실제 불량 중 얼마나 잡았는지입니다. 예를 들어 불량 열 개 중 아홉 개를 잡으면 90퍼센트입니다. 그런데 잡힌 열두 개 중 진짜 불량이 아홉 개라면 Precision은 75퍼센트입니다. F1은 두 지표를 함께 반영합니다. 전부 불량으로 판정하면 Recall만 높아질 수 있으므로 정상 오판도 확인합니다. F1만으로 순위를 정하지는 않습니다.

[4장] 데이터 종류에 맞춰 전처리와 모델을 제안
입력은 두 종류입니다. 센서는 빈 값을 학습 데이터의 중앙값으로 채우고 상수 열을 제거합니다. KNN이나 SVM처럼 단위 차이에 민감한 모델에는 Scaling을 적용합니다. 트리는 기본 설정에서 Scaling을 생략합니다. 불량이 부족하면 학습 데이터 안에서만 가중치나 복제를 비교합니다. 모델은 스칼라 Day1, 2, 3과 반도체 교육자료에서 고른 센서 열두 종과 축소 이미지 세 종류입니다. 로그나 시계열 모델은 입력이 달라 이번 센서 모델과 무조건 경쟁시키지 않았습니다.

[5장] 계획을 승인받고 학습·검증·마지막 확인
먼저 Agent가 데이터 문제와 비교 계획, 근거를 보여 줍니다. 승인하기 전에는 학습하지 않습니다. 데이터를 학습, Validation, Test 세 구간으로 나눕니다. Validation은 학습이 잘 됐는지 검증하고 후보와 판정 경계값을 비교하는 데 사용합니다. Test는 후보를 고르는 데 쓰지 않고 마지막 확인에 남겨 둡니다. 같은 lot이 다른 구간에 섞이지 않게 했습니다. 전체 제품에서 모든 모델을 먼저 비교하고 상위 두 알고리즘만 제품 조합을 확장하기 때문에 완전탐색은 아닙니다.

[6장] 불량은 더 찾았지만, 목표에는 아직 못 미침
합성 센서의 실제 결과입니다. Validation으로 고른 후보는 CatBoost이고 학습 제품은 A+B+C입니다. 같은 Test에서 기본 모델은 불량 25개 중 17개, 후보는 19개를 발견했습니다. 대신 정상 오판은 1개에서 8개로 늘었습니다. Validation에서는 불량 34개를 모두 찾았어도 다른 Test에서는 19개만 찾을 수 있습니다. 그래서 후보로 골랐다는 말과 적용을 승인한다는 말은 다릅니다. 여기서는 Recall 데모 목표 90퍼센트에 못 미쳐 재검토합니다. 90퍼센트와 정상 오판 15퍼센트는 회사 기준이 아닌 시연 기본값입니다.

[7장] 기존 모델 점검 후, 승인받아 같은 알고리즘 재학습
이번에는 공정이 바뀌었다고 가정해 불량 발생 규칙을 바꾼 새 합성 데이터를 넣었습니다. 기존 모델과 판정값을 그대로 두고 같은 제품별로 점검합니다. 성능이 부족하면 재학습을 제안합니다. 승인 뒤 같은 CatBoost 알고리즘을 새 데이터로 다시 학습했습니다. 새 배치의 같은 Test에서 불량 발견은 24개에서 117개로 늘었고 놓친 불량은 103개에서 10개로 줄었습니다. 정상 오판은 70개에서 68개입니다. 다만 정상 오판률 15.1퍼센트가 시연 목표 15퍼센트를 조금 넘으므로 바로 적용한다고 말하지 않습니다. 기존 모델을 운영 중이라고 가정한 모의 검증이며 실제 공정 변화 실측이 아닙니다.

[8장] 여러 제품을 합칠까, C만 따로 학습할까?
여기서 공통 권고나 전용 권고라는 말은 쓰지 않겠습니다. 새 데이터의 A B C D를 모두 합쳐 학습하는 방법과 C만 학습하는 방법을 비교한 것입니다. 같은 C의 Validation에서 C만 학습한 후보가 검출률 96.2퍼센트, 정상 오판률 13.8퍼센트로 데모 목표를 만족했습니다. 하지만 별도 Test의 검출률은 86.1퍼센트여서 다시 확인해야 합니다. 제품마다 결과가 다르므로 제품별 학습이 항상 좋다고 결론 내리지 않습니다. 새 배치 안의 학습 범위를 비교한 것이며 과거 데이터를 자동 병합하는 기능은 아닙니다.

[9장] 실제 공개 반도체 센서에서도 실패를 확인
SECOM은 UCI가 공개한 반도체 공정 데이터셋의 이름입니다. 공정 센서와 합격 불합격 결과가 있고 2008년에 공개됐습니다. 실제 특정 회사의 현재 데이터라고 말할 수는 없습니다. 제품 A B C D 구분도 없어서 이 실험은 단일 제품으로 평가했습니다. 최종 Test에서 불량 15개 중 6개만 발견하고 정상 249개 중 73개를 오판했습니다. 합성 이미지도 불량 14개 중 6개를 발견했습니다. 정상 오판이 없어도 불량을 놓치면 좋은 모델이라고 할 수 없습니다. 실패도 그대로 기록하고 추천을 보류하는 것이 이 Agent의 역할입니다.

[10장] 계획의 이유와 판정 건수를 한 화면에서
화면에서는 먼저 연습용 센서 데이터를 고르고 완료된 결과를 보겠습니다. 불량 몇 개를 찾고 몇 개를 놓쳤는지부터 읽을 수 있습니다. 새 계획에서는 왜 Scaling이나 가중치를 쓰는지 확인하고 승인할 수 있습니다. 다음으로 새 데이터에서 기존 모델을 점검하고 재학습 계획을 받습니다. 로컬 주소는 localhost 8700입니다. 컴퓨터를 재부팅하면 프로젝트 폴더의 start.command를 실행해 서버를 켭니다.

[11장] 설명·계획은 Agent, 실행은 승인 뒤에
Agent 역할은 데이터 품질 점검, 계획 제안, 결과 검토로 나눴습니다. 근거 검색은 교육 내용을 요약한 문서와 공개 자료를 사용합니다. 로컬 Qwen을 실제 호출하고 허용한 판단과 검색 출처를 검사합니다. 품질 점검과 계획 역할은 통과했고 결과 검토 역할은 응답 검사에 실패해 규칙 설명을 사용했습니다. 수치는 LLM이 만들어내지 않고 실험 엔진이 계산합니다. MCP 네 도구와 의존성 주입, 모듈화, 테스트를 구현했습니다.

[12장] 모델 선택과 재학습을 돕는 주제로 완성
이 프로젝트의 주제는 수율 숫자를 바로 올리는 AI가 아니라 불량 판정 모델을 고르고 유지하는 엔지니어를 돕는 Agent입니다. Recall을 우선해 불량을 놓치는 일을 줄이고, Precision과 F1, 정상 오판도 함께 설명합니다. 회사 공통의 합격 수치는 공개 자료로 확인하지 못했습니다. 지금 설정은 시연 값이며 실제 도입에는 제품과 공정 담당자의 기준과 독립 기간 검증이 필요합니다. 현재 작은 표본과 합성 데이터, 반복 Validation 비교가 한계입니다. 기업용 클라우드 확장 구조는 제공하지만 실제 배포나 생산 적용을 검증한 것은 아닙니다. 감사합니다.

[13장] 상세 지표와 재현 조건
필요할 때 보여 줄 부록입니다. Recall은 TP 나누기 TP 더하기 FN, Precision은 TP 나누기 TP 더하기 FP입니다. F1은 2TP 나누기 2TP 더하기 FP 더하기 FN입니다. 정상 오판률은 FP 나누기 FP 더하기 TN입니다. 목표 충족 후보가 없으면 목표와의 차이가 작은 참고 후보만 표시하며 적용 추천이 아닙니다. 완전 동률의 결정 규칙은 trial ID이며 제품 학습 방식 완전 동률은 관리할 모델이 적은 합친 학습입니다. test는 순위 선택에 쓰지 않습니다. 결과는 데이터와 모델뿐 아니라 전처리, 학습 범위, 가중치, 판정 경계값을 포함한 절차 비교입니다.

[14장] 기술 요소가 반영된 위치
기술 요소가 어디에 반영됐는지 연결한 부록입니다. Multi-Agent는 품질 점검과 계획, 결과 검토 역할입니다. RAG는 근거 요약문 검색과 출처 연결에 사용합니다. MCP는 네 도구와 지식 resource를 제공하고 실제 연결을 검증했습니다. 의존성 주입으로 Store와 Knowledge, Advisor를 바꿔 사용할 수 있습니다. 데이터와 학습, 모델 관리, 접속을 모듈로 나누고 스물여섯 개 테스트를 통과했습니다. 구현 위치와 실행 기록은 체크리스트 문서에 연결했습니다.

질문 대비
Q. 재학습이 왜 필요한가요?
A. 같은 제품이라도 공정·장비·재료·데이터가 달라지면 기존 모델의 성능이 달라질 수 있습니다. 기존 모델과 판정값을 고정해 새 정답 데이터에서 점검하고, 부족할 때 승인받아 재학습을 비교합니다. 점검만으로 변화의 원인을 확정하지는 않습니다.

Q. 왜 고른 모델을 바로 적용하지 않나요?
A. Validation에서 고른 후보가 별도 Test나 회사 기준까지 만족한다는 보장은 없기 때문입니다. 후보 선정, 마지막 확인, 회사 적용 승인은 다른 단계입니다.

Q. 15%는 회사 기준인가요?
A. 아닙니다. 90% 검출률, 15% 정상 오판률, Test 불량20개는 시연용 기본값입니다. 회사 공통 수치를 공개 자료에서 확인하지 못했습니다. 제품·공정 담당자가 별도 기준을 정해야 합니다.

Q. 기업 클라우드에서도 쓰나요?
A. API·MCP·분석 엔진을 분리한 확장 예시는 있지만 실배포는 검증하지 않았습니다. 조직 인증과 권한, 데이터 연결, 학습 worker·모델 registry가 추가로 필요합니다.

Q. 외부 모델을 검색해 스스로 목록을 갱신하나요?
A. 현재는 확장 설계입니다. 실제 실행한 교육 모델 비교와 구분해 설명합니다.
Q. 앙상블 비율도 비교하나요?
A. RF·부스팅 자체는 앙상블이지만 서로 다른 모델의 예측을 섞는 가중치 탐색은 아직 미구현입니다. 확장 시 Validation에서 후보 비율을 비교하고 고정된 Test에서 단일 모델과 확인합니다. 최적은 실험한 후보 안의 최선이라는 뜻입니다.

Q. 학습/Validation/Test는 꼭6:2:2인가요?
A. 정해진 비율은 없습니다. 현재 합성 예시는7:1.5:1.5이며 같은 lot을 섞지 않습니다. SECOM은 날짜 블록 기준이라 행 비율은 달라집니다. Test를 고정하고 불량 표본 수와 시간·lot 경계를 먼저 확인합니다. 점수를 높이려고 분할을 반복해서 바꿨다고 설명하지 않습니다.
