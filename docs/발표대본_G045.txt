G045 김용찬 / 과제 2 / 반도체 검사 모델 관리 Agent
발표 대본 (1~11장 약 5분, 12~14장 질문 대응용 부록)

[1장] 반도체 검사 모델 관리 Agent
안녕하세요. G045 김용찬입니다. 제 프로젝트는 엔지니어가 검사 모델을 비교하고 관리하는 일을 돕는 Agent입니다. 불량을 더 찾는 효과와 정상 제품의 불필요한 검사 부담을 함께 보여주고, 새 데이터에서 재학습이 필요한지도 제안합니다.

[2장] 불량 발견과 정상 추가검사의 차이
먼저 용어를 설명하겠습니다. 불량 열 개 중 여덟 개를 찾으면 불량 발견 비율, Recall은 80%입니다. 정상 백 개 중 다섯 개를 잘못 의심하면 정상 추가검사 비율, FPR은 5%입니다. 정상 추가검사 허용 15%는 정상 백 개 중 최대 열다섯 개라는 뜻입니다. 두 비율의 분모가 다릅니다.

[3장] Agent와 엔지니어의 역할
Agent는 데이터 상태를 점검하고 근거를 검색해서 비교 계획을 만듭니다. 엔지니어가 기준과 실험 수를 확인한 뒤 승인하면 학습을 실행합니다. 결과가 기준에 못 미치면 보류합니다. 승인 기록과 모델 파일도 저장합니다. 현장 운영 모델을 자동 교체하지는 않습니다.

[4장] 데이터에 맞춘 전처리와 모델
이 기능은 왜 이런 전처리를 하고 모델을 썼는지도 설명합니다. 센서의 결측은 학습 데이터의 중앙값으로 채웁니다. KNN과 SVM처럼 거리와 단위에 영향을 받는 모델에는 표준화를 적용합니다. 트리 모델은 단위 표준화가 필수는 아닙니다. 불량이 적으면 가중치나 학습 데이터 안에서의 복제를 비교합니다. 평가 데이터는 바꾸지 않습니다.

[5장] 교육 모델 12종의 실제 비교
스칼라 Day1의 트리와 부스팅, Day2의 KNN과 SVM, Day3의 신경망을 후보로 넣었습니다. 먼저 전체 제품에서 열두 모델과 두 불균형 정책을 비교합니다. 그중 validation 상위 두 모델의 제품 조합을 더 비교해 최대 쉰두 조건을 학습합니다. 모든 조합의 완전탐색은 아닙니다. 이번 합성 예제는 SVM을 선택했지만 최종 기준을 넘어서 적용은 보류했습니다.

[6장] 불량 추가 발견과 추가검사 부담
생산 천 개 중 불량 백 개라는 가정으로 결과를 읽어보겠습니다. 기본 모델은 불량 60개, 선택 모델은 96개를 찾아 36개를 더 발견합니다. 대신 정상 제품 추가검사는 약 134.7개 늘어납니다. 미검출 한 개 십만 원, 정상 추가검사 한 개 천 원이라는 비용 가정에서는 손실이 약 346.5만 원 줄어듭니다. 실제 이익을 측정한 결과는 아니며 검사 부담 기준 초과로 적용은 보류했습니다.

[7장] 재작업 후 양품 비율의 가정
불량을 찾는 것만으로 제조 수율이 오르지는 않습니다. 발견한 불량의 20%를 재작업으로 정상화할 수 있다는 추가 가정을 넣으면, 기본 모델보다 양품 7.2개를 더 회수합니다. 재작업 후 양품 비율은 91.20%에서 91.92%로 0.72%포인트 오릅니다. 실제 반도체 결함을 이 비율로 재작업할 수 있는지는 확인하지 않았습니다.

[8장] 공개 SECOM에서는 적용 보류
실제 공개 데이터인 SECOM도 비교했습니다. 불량 발견 비율은 6.7%에서 93.3%로 올랐지만 정상 추가검사 비율이 88.8%입니다. 대부분의 정상 제품도 다시 검사해야 한다는 뜻입니다. calibration과 validation 기준을 동시에 만족한 후보도 없고 test 불량은 열다섯 개뿐입니다. 따라서 성능이 좋다고 포장하지 않고 보류 사례로 보고합니다.

[9장] 새 데이터의 성능 저하와 재학습
새로운 독립 합성 배치에서는 불량 발생 규칙을 바꿨습니다. 기존 모델의 불량 발견 비율이 이전 test의 96.0%에서 새 train 점검의 39.2%로 내려갔습니다. Agent는 재학습을 제안하고 승인 후 공통 모델과 제품 전용 모델을 생성합니다. 서로 다른 배치의 비교이며 10%포인트 하락 같은 기준은 개발용 규칙입니다.

[10장] 통합 학습과 제품 전용 학습 비교
학습 데이터를 합치는 것이 항상 좋지는 않습니다. 같은 제품의 같은 validation 데이터로 공통 모델과 제품 전용 모델을 비교했습니다. A는 공통, C는 전용을 권고했고 B와 D는 적용을 보류했습니다. C는 표에 보이는 비율이 같아 AP라는 점수 순위 지표로 선택했습니다. 최종 test는 방식을 고르는 데 사용하지 않고 보류 여부를 확인하는 데만 사용합니다.

[11장] 실제 화면의 설명과 승인 흐름
화면에서는 완료된 예시 결과로 추가 불량 발견과 검사 부담을 먼저 읽을 수 있습니다. 모델 선정 이유에는 데이터에 맞춘 전처리와 불균형 대책을 표시했습니다. 새 비교 계획은 승인 전까지 학습하지 않습니다. 새 배치를 준비하면 성능 저하 점검과 통합·전용 후보 생성도 시연할 수 있습니다.

[12장] 과제 기술 항목과 검증 상태
여기부터는 기술 부록입니다. 로컬 LLM 역할과 LangGraph, 임베딩 검색과 생성 입력 연결, MCP, 의존성 주입, 모듈화와 스물여섯 테스트를 구현했습니다. 실제 LLM 통합 검증에서는 품질과 계획 역할이 검사를 통과했고 결과 검토 역할은 출처 검사를 통과하지 못해 규칙 설명으로 대체했습니다. LangSmith 원격 API는 403 권한 오류로 추적 성공을 확인하지 못했습니다. 이 한계도 보고서에 적었습니다.

[13장] 모델별 선택용 데이터 비교
열두 모델의 전체 제품 학습 결과입니다. 각 모델에서 두 불균형 정책 중 validation 기준에 따라 정한 대표 조건을 보여줍니다. 이 표는 모델 선택에 사용한 수치이며 test 성능표가 아닙니다. 이후 상위 두 모델에 대해 제품 학습 조합을 확장했습니다. 모델 이름이 많아도 서로 다른 입력 형식을 한 순위에 넣지는 않았습니다.

[14장] 현재 한계와 확장 방향
이번 프로젝트는 공개 데이터와 합성 데모로 검사 모델 관리 흐름을 구현했습니다. 다음 확장은 외부에서 모델을 검색하고 모델 문서와 과거 실험을 RAG로 참고해서, 데이터에 맞는 새 후보를 승인 후 비교하는 기능입니다. 같은 조건의 검증을 통과하면 후보 목록과 버전을 갱신하는 흐름을 설계했습니다. 이 외부 발굴 기능은 아직 구현하지 않았습니다. 사진의 로그·시계열 모델도 관련 입력을 확보한 뒤 확장할 수 있습니다. 실제 제조 효과는 독립 현장 데이터와 비용 검증이 더 필요합니다. 감사합니다.

질문 대응
Q. 정상 오탐률 상한은 무엇인가요?
A. 정상 제품 중 잘못 의심하여 추가검사하는 비율의 허용 한도입니다. 15%이면 정상 100개 중 최대 15개입니다. 불량을 놓치는 비율과는 분모가 다릅니다.
Q. 이 주제가 과제 2에 맞나요?
A. 신규 Agent 주제에 제한은 없습니다. 현장 의사결정을 근거·수치로 제안하고 승인 후 실행하는 흐름으로 구성했습니다. 기술 항목은 구현과 검증 상태를 구분해서 설명합니다.
Q. 96%면 바로 써도 되나요?
A. 합성 데이터의 최종 불량 25개 중 24개를 찾은 결과입니다. 정상 추가검사가 허용 기준을 넘었고 독립 현장 검증도 없어 적용 보류입니다.
Q. LLM이 숫자나 모델을 마음대로 바꾸나요?
A. LLM은 근거 문서를 보고 허용된 판단의 우선순위를 제안합니다. 수치·실험 예산·승인·선택 기준은 코드가 관리합니다. 출처 연결 검사가 실패하면 규칙 설명을 사용합니다.
Q. 기업 클라우드에서 쓸 수 있나요?
A. API·MCP·배포 예시는 제공하지만 실제 기업 클라우드 배포는 검증하지 않았습니다. 조직 인증·권한과 worker·저장소 연동이 필요합니다.
Q. 단면 길이 측정이나 수율 예측은요?
A. 현재 불량 분류 범위에는 없습니다. 길이 측정은 스케일과 정답 좌표가 있는 이미지, 수율 예측은 lot별 투입·양품 및 공정 조건 이력이 필요합니다.
