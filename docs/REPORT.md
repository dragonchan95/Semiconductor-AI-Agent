## 2. 문제 개선 및 신규 구현 사항

### 해결할 문제

이 신규 구현 프로젝트에서 설정한 기존 업무 방식은 **엔지니어가 검사 데이터의 학습 제품 범위·모델·혼합 비율을 직접 비교하고, 선택 근거와 결과를 정리하며 새 생산 데이터에서 기존 모델의 성능도 확인해야 하는 상황**입니다. 비교 계획·승인·실행·기록을 연결해 그 선택을 돕는 것을 해결 과제로 정했습니다. 특정 회사의 기존 시스템을 조사하거나 업무시간·기존 성능을 실측한 프로젝트는 아닙니다.

| 개선 대상 | 신규 구현 | 확인 방법 |
|---|---|---|
| 반복적인 데이터·전처리 확인 | 결측·불균형·생산 묶음 점검과 근거 제시 | 데이터·계획 화면 |
| 학습할 제품 범위 선택 | ABCD 하나, ABC와D, AB와CD, 각각4개 등15개 그룹 구성 비교 | 같은 Validation의 구성별·제품별 점수 |
| 모델 예측을 섞을 비율 선택 | 단일·균등·5% 간격을 포함한232개 비율 비교 | 비율별 Recall·F1·정상 오판률과 CSV |
| 근거 없이 학습·선택 | 계획·데이터 hash를 확인한 단회 승인 후 실행 | 미승인·중복 승인 차단 |
| 높은 점수만 보고 적용 | 선택 후 Test 확인 및 목표 미달·표본 부족 시 보류 | 그룹 실험의 실제 보류 결과 |
| 데이터 변화 후 기존 모델 관리 | 새 정답 배치 점검·재학습 제안·승인·동일 Test 전후 비교·후보 저장 | [실제 Mac 실행](evaluation/lifecycle_mac.json)과 관리 화면 |
| 비교 후보를 추가하기 위한 문서 탐색 | 공식 문서 검색과 근거 연결 RAG | ExtraTrees·GaussianNB 후보·출처 화면 |

모델·제품 그룹·앙상블 비율을 한 번에 공동 전역 최적화했다고 주장하지 않습니다. **알고리즘을 고정한 제품 그룹 실험**과 **학습 제품ABCD를 고정한 앙상블 실험**을 각각 수행했습니다.

승인은 저장된 계획 hash·데이터 버전과 단회 실행 상태로 확인합니다. LangGraph interrupt를 사용한 구현은 아닙니다. 제품 그룹 실험과 비율 실험은 별도 승인된 비교이며 자동 운영 모델 교체는 수행하지 않습니다.

### 교육 모델과 데이터 범위

입력 종류에 따라 모델이 달라집니다. 교육자료의 센서 분류 모델12종(Logistic Regression, Tree·Forest·Boosting, KNN, SVM, MLP 등)과 검사 이미지용 축소 ResNet·VGGNet·Autoencoder3종을 실제 학습합니다. 이미지 학습은 교육용 축소 구조이며 원 논문의 전체 모델 성능을 재현했다고 주장하지 않습니다. EfficientNet·GAN과 GPT/BERT 로그 분류·LSTM/ARIMA 시계열은 미구현 확장 후보입니다. 시계열의 연속 입력·예측 목표와 장비 로그·정답 데이터가 준비되지 않아 현재 학습 비교에서 제외했습니다. Agent 설명용 Qwen과 장비 로그 분류 모델은 역할이 다릅니다. [수업 PDF 쪽·모델·전처리 연결표](CURRICULUM_MODELS.md)

공개 예제 **SECOM은 UCI Machine Learning Repository의 반도체 제조 센서·정상/불량 데이터셋**입니다. McCann & Johnston(2008), DOI10.24432/C54305, CC BY4.0이며 일본 경비 회사 자료를 뜻하지 않습니다. 1,567개 샘플 중 불량104개이고 센서 원파일590열입니다. UCI 메타데이터의591 features 표기와 구분합니다. 제품명·회사명은 제공하지 않습니다. [UCI 원본 및 라이선스](https://archive.ics.uci.edu/dataset/179/secom)

나머지 제품 A–D 센서·검사 이미지 예제는 합성 자료입니다. SECOM은 날짜 블록 기준으로60/20/20을 나누어 실제 행 수820/367/380이며, 제품 A–D 센서는 lot 단위6:2:2로 나눕니다. 본문 그룹·앙상블과 개별 모델표의 수치는 합성 센서1,280건을 실제 학습해 측정한 값입니다. 임의로 꾸민 성능 수치가 아닙니다. 모델 관리 실험은 변화 규칙을 바꾼 별도 합성 배치3,840건이며, 이미지 실험도 별도 합성576건입니다. 서로 다른 데이터의 점수로 모델 우열을 직접 비교하지 않습니다.

실제 공개 SECOM도 별도로 실행했습니다. 선택 XGBoost의 Test380건(불량23·정상357)에서 불량5개를 발견하고 정상87개를 오판해 Recall21.7%·정상 오판률24.4%로 목표에 미달했습니다. [실제 실행 원본](evaluation/secom.json). 합성 실험의 좋은 점수가 실제 제조 환경에서도 유지된다는 근거로 사용할 수 없습니다.

### 시연 시나리오와 화면

제품 A–D 합성 센서1,280건(불량201건)을 선택합니다. 생산 묶음을 섞지 않고 Train768 / Validation256 / Test256으로 나눕니다. 원본 행·라벨·분할을 고정한 뒤 두 실험을 각각 진행합니다.

1. 데이터를 선택하고 점검·근거·비교 계획을 확인합니다.
2. 계획을 승인해 실제 학습합니다. 후속 그룹·비율 계획도 별도로 승인합니다.
3. Validation에서 선택한 구성·비율·판정 기준을 고정합니다.
4. Test에서 목표와 표본을 확인하고, 실패하면 적용 보류를 표시합니다.
5. 전체 후보 점수와 선택 근거를 JSON·CSV로 확인합니다.

### 실험1: 어떤 제품을 함께 학습할까요?

CatBoost 알고리즘과 설정을 고정해15개 담당 그룹 구성을 모두 비교합니다. 비어 있지 않은 학습 묶음15개를 한 번씩 적합해 재사용합니다. 각 구성은 전체 제품을 중복·누락 없이 담당하며 같은 Validation 행에서 비교합니다. 제품별 정상 오판 한도와 검출 목표를 확인한 뒤 전체 Recall·F1, 동률이면 모델 수를 고려합니다.

| 구성 | 모델 수 | Validation Recall | Validation F1 | Test Recall | Test F1 |
|---|---|---|---|---|---|
| A+B+C+D | 1 | 100.0% | 0.808 | 93.8% | 0.723 |
| A+B+C / D | 2 | 100.0% | 0.840 | 78.1% | 0.704 |
| A / B / C / D | 4 | 90.5% | 0.731 | 78.1% | 0.725 |

Validation 선택은 **A+B+C / D**입니다. 하지만 Test Recall **78.1%**로 목표90% 미달이며 제품별 표본도 작아 **적용 보류**를 표시했습니다. Test에서 공통 모델 점수가 더 높았다고 선택 구성을 다시 바꾸지 않았습니다. 실패 결과도 보존했습니다.

### 실험2: 예측을 어떤 비율로 섞을까요?

학습 제품ABCD를 고정하고 CatBoost·HistGradientBoosting·LightGBM을 구성 후보로 사용합니다. 합계100% 비율을5% 간격으로 모두 비교하고 균등 비율도 포함했습니다. 단일 모델도 포함하며 성능이 같으면 적은 모델을 사용합니다. **정상 오판 한도 안에서 Recall 최대 → 동률 F1** 순서로 비율과 판정 기준을 Validation에서 고릅니다.

| Validation 비교 | Recall | 정상 오판률 | F1 |
|---|---|---|---|
| 최선 단일 | 100.0% | 9.3% | 0.808 |
| 균등 혼합 | 100.0% | 10.3% | 0.792 |
| 선택90:0:10 | 100.0% | 8.9% | 0.816 |

| 선택 후 같은 Test | 최선 단일 CatBoost | 선택 CatBoost90%+LightGBM10% |
|---|---|---|
| 불량 발견 | 30/32 | 30/32 |
| 정상 오판 | 21/224 | 19/224 |
| Recall | 93.8% | 93.8% |
| F1 | 0.723 | 0.741 |

선택 비율은 **CatBoost90% + LightGBM10%**이며 HistGradientBoosting은0%입니다. 승인한 후보·간격·Validation 범위 안의 최선입니다. 전체 알고리즘과 모든 연속 비율의 전역 최적을 뜻하지 않습니다.

### 실험3: 기존 모델의 성능이 떨어졌다면요?

이 기능은 **같은 제품의 새 정답 데이터로 기존 모델을 점검하는 배치 방식**입니다. 13주차 CMP 프로젝트의 점검·재학습·승인 개념을 참고했지만, 회귀 잔차의 3시그마 기준을 분류 모델에 그대로 적용하지 않았습니다. 입력값 분포만으로 성능 하락을 확정하지 않으며 상시 감시 기능은 아닙니다.

1. 기존 완료 결과의 **모델 성능 점검·재학습**을 누릅니다.
2. 별도 후속 배치를 선택하고 기존 모델·판정 경계값을 고정해 점검합니다.
3. 제품별 새 불량20개 이상에서 목표 미달 또는 Recall이 이전보다10%p 넘게 떨어지면 재학습 비교를 제안합니다. 표본이 부족한 제품이 있으면 전체를 정상 유지로 단정하지 않고 판단을 보류합니다.
4. 엔지니어가 확인·승인하면 같은 알고리즘으로 새 Train을 학습합니다. 전 제품 공통 모델1개와 제품별 모델4개의 계획도 비교합니다.
5. Validation에서 후보를 정하고, 남겨 둔 같은 Test에서 기존·재학습 모델의 전후 수치를 보여 줍니다. 후보와 버전 기록을 저장하고 운영 모델은 유지합니다.

90% 검출 목표·15% 정상 오판 한도·불량20개·10%p 하락은 **교육용 규칙**입니다. 회사 공통 기준이나 통계적으로 확증한 드리프트 경계가 아닙니다. 이전 제품별 불량 표본도 작으므로 하락 폭은 탐색적으로 해석합니다. 정답이 없는 데이터만으로는 Recall을 계산할 수 없습니다.

![새 정답 데이터로 기존 모델 점검](assets/app-management-review.jpg)

후속 합성 배치는 독립 seed1045로 결함 발생 규칙을 바꾼3,840건입니다. 같은 lot을 분리하지 않는 목표6:2:2 분할로 Train2,304 / Validation768 / Test768건을 사용했습니다. 점검은 새 Train 구간에 한정하고 새 Validation/Test를 재학습 필요성 판단에 사용하지 않았습니다. 아래는 재학습 비교의 실제 실행 결과이며 앞의1,280건 실험과 다른 데이터입니다.

| 새 배치의 같은 Test 768건 | 기존 CatBoost 그대로 | 같은 CatBoost 재학습 |
|---|---|---|
| 불량 발견 | 43/167 | 153/167 |
| 놓친 불량 | 124/167 | 14/167 |
| 정상 오판 | 96/601 | 79/601 |
| Recall | 25.7% | 91.6% |
| 정상 오판률 | 16.0% | 13.1% |
| F1 | 0.281 | 0.767 |

![승인 재학습 후 같은 Test에서 비교](assets/app-management-result.jpg)

재학습은 기존 트리에 이어 학습한 것이 아니라 **동일 알고리즘을 새 Train으로 다시 적합한 것**입니다. 운영 중인 회사 모델을 교체하거나 실제 수율이 개선된 실적은 아닙니다. 과거 배치 파일을 자동 병합하지 않으며, 공통·제품별 후보는 같은 새 배치의 Validation으로 선택합니다. [실행 원본과 승인 기록](evaluation/lifecycle_mac.json) · [기능·판단 기준](MODEL_MANAGEMENT.md)

### 근거 검색과 설명 검사

외부 모델 탐색에도 RAG를 사용합니다. **공식 모델 문서 수집 → BGE-M3 의미 임베딩 → FAISS 검색 → 검색 근거를 로컬 Qwen에 전달 → 후보 제안 → 엔지니어 승인 후 비교** 순서입니다. 정규화한 벡터는 FAISS IndexFlatIP에, 출처·문서 내용은 JSON에 저장하고 문서나 설정이 바뀌면 다른 인덱스를 만듭니다. 수업은 SentenceTransformer로 실행했고 현재 Mac·Windows는 같은 BGE-M3 계열을 Ollama로 로컬 실행합니다. 학습 연결은 사전 검토된 ExtraTrees·GaussianNB 두 후보입니다. 문서 검색이 임의 모델의 자동 설치나 성능 우위 확인을 뜻하지는 않습니다.

![공식 문서의 후보·근거](assets/app-rag-proof.jpg)

LLM-as-a-Judge는 실제 결과와 설명을 함께 보고 맞는 설명인지 검사합니다. 이전 실험의 실제27개 발견을30개라고 바꾼 오류를 놓친 사례도 있습니다. 정답 여부8개 중6개 판단 일치는 설명 검사 예제의 결과이며 분류 모델 정확도가 아닙니다. 원래 실패 기록과 기준 실험을 보존합니다. [평가 원본](evaluation/llm_judge.json)

## 5. 교훈

### 한계와 트레이드오프

- 제품별로 나누면 제품 특성을 반영할 수 있지만 학습 데이터·불량 표본은 줄고 관리할 모델 수는 늘어납니다.
- 전체 점수로 제품별 실패를 숨기지 않도록 제품별 정상 오판률·검출률·표본을 함께 확인했습니다.
- 그룹 실험은 Validation에서 좋았지만 Test에서 실패했습니다. 선택 근거와 적용 가능성은 별도로 판단해야 합니다.
- 합성 데이터, 단일 seed, 작은 제품별 불량 표본, 같은 Validation의 반복 선택이 한계입니다. 기존 프로젝트에서 이미 확인한 Test를 추가 탐색에 재사용했으므로 독립적인 최종 검증 실적이 아닙니다.
- 새 배치 점검은 정답이 필요합니다. 교육용 규칙은 성능 변화의 통계적 확증이 아니며 상시 입력 드리프트 감시·자동 운영 교체는 구현하지 않았습니다.
- 그룹·알고리즘·앙상블 비율의 공동 전역 최적화, 회사 공통 합격 기준, 수율·금액 이익·작업시간 절감·자동 배포는 검증하지 않았습니다.
- LLM 설명 검사도 오판합니다. RAG는 BGE-M3·FAISS 로컬 벡터 저장·검색이며 별도 서버형 DB·자율 Supervisor를 구현했다고 주장하지 않습니다. 작은 고정 검색 질문은 독립적인 일반 검색 평가가 아닙니다.

### 향후 개선

현장 담당자와 허용할 미검출·정상 오판 범위를 먼저 합의합니다. 새 독립 기간·생산 묶음으로 검증하고 반복 분할·교차검증과 제품별 불확실성을 평가합니다. 그 뒤 필요하면 중첩 검증으로 그룹·모델·비율 탐색을 확장하고, 문서 규모와 동시 사용자가 늘면 서버형 Vector DB를 평가합니다. 실제 엔지니어의 작업시간도 측정합니다. 상시 감시는 생산 데이터 수집 주기·정답 도착 지연·알림 정책을 연결하고, 운영 모델 교체는 승인·단계적 적용·버전 복구까지 검증한 뒤 확장합니다.

### 수행 소감과 배운 점

높은 점수 하나를 보여 주기보다 무엇을 고정하고 무엇을 비교했는지를 명확히 해야 선택을 설명할 수 있었습니다. 제품별 전용 모델과 앙상블이 항상 더 좋은 것은 아니었습니다. LLM의 설명과 코드가 계산한 숫자·승인 권한을 분리하고, 실패·보류를 기록하는 것이 중요했습니다. 환경 이동 과정에서는 모델·설정·실험 이력의 복원과 Windows SQLite 연결 종료도 확인해야 했습니다.
