# 외부 모델 발굴과 후보 목록 갱신

현재 구현은 교육 모델12종과 이미지3종의 승인된 후보군을 실제 비교합니다. 아래는 확장 설계이며 실행 기능으로 구현하지 않았습니다.

외부 검색 도구가 공식 모델 문서·논문·모델 카드를 수집합니다. 데이터 종류, 입력 형태, 과제, 학습 표본, 평가 지표, 라이선스, 메모리와 예상 학습 시간을 기록합니다. 새 후보는 먼저 `발굴됨` 상태로 저장하며 출처와 조회 시각을 남깁니다. RAG는 이 문서와 과거 실험의 성공·실패 기록을 찾아 적합성 판단과 비교 계획에 연결합니다. 검색 도구와 RAG는 다른 역할입니다.

엔지니어가 구현 방식·실험 예산을 확인하고 승인한 후보만 격리된 학습 환경에서 비교합니다. 모델 adapter는 입력·fit·점수·직렬화 계약을 맞추고 단위 테스트를 통과해야 합니다. 웹 문서의 설치 명령이나 코드가 바로 실행되는 구조로 만들지 않습니다. 원본 공정 데이터는 외부 검색에 보내지 않고 데이터 종류와 과제 요약만 사용합니다.

기존 모델과 같은 분할·비용 가정으로 validation 성능, 불량 발견, 정상 추가검사, 학습·추론 시간과 자원 사용을 비교합니다. test를 반복해서 보며 목록을 튜닝하지 않고 독립 기간 검증 또는 보류 데이터를 별도로 운영합니다. 승인된 검증을 통과하면 `검증 완료` 후보 목록을 갱신하고 실패·보류도 기록합니다. 모델 후보 등록과 생산 운영 모델 교체는 별개 상태입니다.

확장 예시 상태: 발굴됨, 적합성 검토, 구현·시험 대기, 승인된 실험, 검증 완료, 보류. 새로운 모델이 항상 우수하다는 가정은 두지 않습니다. 성능이 비슷하면 더 빠르고 단순한 기존 모델을 유지할 수 있습니다.

근거: [Hugging Face 모델 카드](https://huggingface.co/docs/hub/model-cards)는 용도·한계·학습 및 평가 정보를 담습니다. [MLflow Model Registry](https://mlflow.org/docs/latest/ml/model-registry/)는 모델 버전과 메타데이터를 관리하는 구현 참고입니다. 이 프로젝트에 MLflow를 설치·연동한 것은 아닙니다.
