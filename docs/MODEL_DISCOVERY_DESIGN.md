# 외부 모델 발굴과 후보 목록 갱신

현재 구현은 교육 모델12종과 이미지3종의 승인된 후보군을 실제 비교합니다. 아래는 확장 설계이며 실행 기능으로 구현하지 않았습니다.

외부 검색 도구가 공식 모델 문서·논문·모델 카드를 수집합니다. 데이터 종류, 입력 형태, 과제, 학습 표본, 평가 지표, 라이선스, 메모리와 예상 학습 시간을 기록합니다. 새 후보는 먼저 `발굴됨` 상태로 저장하며 출처와 조회 시각을 남깁니다. RAG는 이 문서와 과거 실험의 성공·실패 기록을 찾아 적합성 판단과 비교 계획에 연결합니다. 검색 도구와 RAG는 다른 역할입니다.

엔지니어가 구현 방식·실험 예산을 확인하고 승인한 후보만 격리된 학습 환경에서 비교합니다. 모델 adapter는 입력·fit·점수·직렬화 계약을 맞추고 단위 테스트를 통과해야 합니다. 웹 문서의 설치 명령이나 코드가 바로 실행되는 구조로 만들지 않습니다. 원본 공정 데이터는 외부 검색에 보내지 않고 데이터 종류와 과제 요약만 사용합니다.

기존 모델과 같은 분할·비교 목표로 Validation의 Recall을 우선 비교하고 Precision·F1·정상 오판률과 학습·추론 시간도 확인합니다. Test를 반복해서 보며 목록을 튜닝하지 않고 독립 기간 검증 또는 보류 데이터를 별도로 운영합니다. 승인된 검증을 통과하면 `검증 완료` 후보 목록을 갱신하고 실패·보류도 기록합니다. 모델 후보 등록과 생산 운영 모델 교체는 별개 상태입니다.

확장 예시 상태: 발굴됨, 적합성 검토, 구현·시험 대기, 승인된 실험, 검증 완료, 보류. 새로운 모델이 항상 우수하다는 가정은 두지 않습니다. 성능이 비슷하면 더 빠르고 단순한 기존 모델을 유지할 수 있습니다.

근거: [Hugging Face 모델 카드](https://huggingface.co/docs/hub/model-cards)는 용도·한계·학습 및 평가 정보를 담습니다. [MLflow Model Registry](https://mlflow.org/docs/latest/ml/model-registry/)는 모델 버전과 메타데이터를 관리하는 구현 참고입니다. 이 프로젝트에 MLflow를 설치·연동한 것은 아닙니다.


## 추가 확장: 앙상블 가중치 비교 (미구현)

현재 RF·Gradient Boosting·XGBoost 등 앙상블 알고리즘은 실제 후보에 포함되어 있습니다. 서로 다른 모델의 예측을 섞는 가중치 탐색은 구현하지 않았습니다. 확장 시 동일 입력·동일 라벨 정의의 상위 센서 모델 두 개에 대해 사전 정의한 비율(예: 0:100,25:75,50:50,75:25,100:0)을 Validation에서 비교합니다. Recall을 우선하고 정상 오판 목표도 확인하며, 단일 모델보다 나아지는 경우에만 후보로 제시합니다. 앙상블은 학습·추론 자원과 관리할 모델 수를 늘릴 수 있습니다. “최적”은 실험한 후보 안의 최선이며 전역 최적이나 현장 성능 보장이 아닙니다. 엔지니어 승인을 받은 뒤 학습하고 고정된 Test를 마지막에만 확인합니다.

학습/Validation/Test는 반드시6:2:2가 아닙니다. 현재 합성 예시는 lot 기준7:1.5:1.5, SECOM은 날짜 블록 기준으로 나눠 실제 행 비율은 다릅니다. 비율을 점수에 맞춰 반복 조절하면 평가 표본 차이와 모델 개선을 구분하기 어려우므로 현재 Agent는 비율을 자동 튜닝하지 않습니다. 확장 시 Test를 먼저 고정하고 학습·Validation 내부에서만 lot/시간을 지키는 교차검증으로 후보를 비교합니다. 불량이 희소하면 비율보다 평가에 포함된 불량 수와 기간 대표성이 중요합니다.

근거: [scikit-learn 앙상블·Voting](https://scikit-learn.org/stable/modules/ensemble.html#voting-classifier), [교차검증과 Test 분리](https://scikit-learn.org/stable/modules/cross_validation.html).
