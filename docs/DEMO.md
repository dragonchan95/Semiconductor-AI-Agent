# 발표와 앱 실행

본문 1~10장만 발표하고 11~14장은 질문 때만 엽니다. 발화 목표255초, 전환20초, 여유25초로 5분을 준비합니다. 실제 리허설 측정값은 아닙니다. 출처 목록과 중복 기술표는 슬라이드에서 제거하고 README·보고서에 남겼습니다.

| 장 | 설명할 질문 | 목표 시간 |
|---|---|---:|
| 1 | 무엇을 만들었나요? | 15초 |
| 2 | 누구의 어떤 반복 업무를 돕나요? | 20초 |
| 3 | 무엇을 좋은 모델로 볼 건가요? | 25초 |
| 4 | 어떤 데이터를 넣나요? 실제 입력 화면 | 20초 |
| 5 | 개별 모델 비교 후 비율 탐색 계획을 어떻게 승인하나요? | 25초 |
| 6 | 왜 CatBoost90%·LightGBM10%를 선택했나요? | 35초 |
| 7 | 남겨 둔 데이터에서 실제 결과는 어떤가요? | 35초 |
| 8 | 비교할 후보를 더하려면 어떻게 하나요? | 25초 |
| 9 | 어떤 기술로 연결하고 검증했나요? | 35초 |
| 10 | 성과·교훈·한계·다음 개선은 무엇인가요? | 20초 |

기존 부록의 Recall 설명은 3장으로 통합했습니다. 지표→선택→결과 순서로 설명하고 부록에서 같은 내용을 다시 발표하지 않습니다. 아키텍처는 기능 시연 뒤에 배치했습니다.

필수 화면은 입력(4), 앙상블 계획·승인(5), Validation 비율 비교(6), 같은 Test의 결과·판단(7), RAG 후보·공식 근거(8)입니다. 5~7장은 실제 Windows UI에서 계획·승인·학습·비율 탐색을 실행한 화면입니다. 기록은 `evaluation/weighted_ensemble.json`과 `evaluation/ensemble_browser.json`에 있습니다. 8장은 보존된 실제 공식 문서 검색 기록의 UI 재현이며 새 검색 성공을 뜻하지 않습니다. 원본은 `evaluation/model_discovery.json`입니다.

슬라이드 노트의 대본만 읽고, 표의 모든 행이나 부록은 읽지 않습니다. 6장은90:10을 고른 근거, 7장은불량30/32동일·정상오판21→19·F1 .723→.741에 집중합니다. 정상 오판 한도 안에서 Recall을 먼저 높이고 동률이면 F1으로 고르는 규칙을 먼저 설명합니다. 타이머로 한 번 읽어 실제 속도를 확인하고, 5분을 넘으면 8장 모델명 설명을 줄입니다. 발표 중 새 학습이나 검색을 기다리지 않습니다.

Windows에서는 start.cmd를 실행한 뒤 http://localhost:8700을 엽니다. 이 노트북에는 합성 센서 실험 이력이 준비되어 있습니다.
제품 A–D 센서를 선택하고 결과 보기 → 저장된 앙상블 결과 보기로 확인합니다. 새 비율 비교는 개별 결과의 앙상블 비율 비교 계획 → 계획 검토 → 승인·학습 순서입니다.

결과의 모델별 Validation 비교에서 후보 선택 이유를 확인합니다. 공식 문서에서 비교 후보를 추가하거나 목표를 검토할 수 있습니다. 재학습·기존 모델 점검은 접힌 부가 기능으로 남겨 두고 발표에서 제외합니다.
발표는 저장된 실제 화면을 설명하므로 학습을 새로 기다리지 않아도 됩니다.

현재 Windows는 수업과 같은 Qwen2.5-1.5B 계열을 로컬로 실행합니다. 세 역할의 실제 응답·허용 코드·출처 연결 검사를 확인했고 LangSmith APAC 추적은 별도로 검증했습니다. 모델·코드·근거 조합에 따른 응답 검사 실패는 규칙 설명으로 표시합니다.
노트북 CPU에서 계획 생성에는 수십 초가 걸릴 수 있으므로 발표 때는 준비된 화면을 설명합니다.
기존 Google Slides의 온라인 갱신은 Google Drive 연결 후 확인해야 합니다.
자세한 환경 이동 내용은 HANDOFF_WINDOWS.md를 참조합니다.
