# 발표 및 코드 설명 안내

G045 김용찬, 과제 2 신규 프로젝트. 보고 순서는 **문제 → 구현 → Before/After → 한계·추가 개선**입니다.

## 5분 발표 흐름

1. **문제(40초)**: 불량은 적고 모델·학습 제품·전처리 조합은 많다. Recall만 높이면 정상 제품 과검출이 늘 수 있다. 엔지니어가 실행 전 계획과 평가 기준을 검토할 도구가 필요했다.
2. **구현(90초)**: 데이터 검사, 근거 검색, 실험 계획의 세 LangGraph 역할을 설명한다. 전체 부분집합 15개와 두 모델, 불균형 정책 두 개를 조합해 60개 후보를 만든다. 승인 전에는 모델을 학습하지 않는다.
3. **시연(60초)**: 합성 공정 선택 → 계획 요청 → 데이터 품질·60개 예산·근거 확인 → 승인 → 결과 표시. 반려·중복 실행 차단을 설명한다. SECOM 결과도 열어 배포 보류를 보여준다.
4. **수치(50초)**: 합성 공정 Recall 60→100%, 공개 SECOM 6.7→60%. SECOM Precision 5.2%, FPR65.5%를 반드시 함께 말한다. 공개 데이터에서 운영 목표를 만족하지 못했다.
5. **한계(40초)**: 단일 seed와 작은 표본, 결정적 역할 노드, 합성 이미지의 단순성, 미검증 클라우드 배포. 다음 단계는 실제 라벨·시간 정보, 반복 시계열 검증과 SSO/worker 분리다.

## 코드에서 설명할 곳

| 파일 | 설명할 핵심 |
|---|---|
| `app/planner.py` | 의존성을 주입받아 LangGraph 노드를 조립. TF-IDF 검색 후 실제 데이터와 예산에 맞는 계획 생성 |
| `app/data.py` | 정상0/불량1, SECOM 원본 해석, lot·날짜 분할, valid zero 보존과 중복·누락 검증 |
| `app/store.py` | 계획 hash와 SQLite 트랜잭션. 승인 상태와 단일 실행 보장 |
| `app/workbench.py` | API·MCP·노트북이 공유하는 서비스 계층 |
| `app/experiments.py` | train 전용 Pipeline, calibration 임계값, validation 선택, 마지막 test |
| `app/images.py` | 축소 residual·VGG·Autoencoder 실제 학습. Autoencoder 정상 전용 학습 |
| `app/metrics.py` | 혼동행렬, Recall·Precision·FPR·AP, 비용 가정 및 보류 기준 |
| `app/api.py` | 업로드, 승인 API, 비동기 실행, 이력·CSV, production 토큰 |
| `mcp_server.py` | 읽기·계획 도구만 노출. 승인·실행 권한은 엔지니어 UI에 유지 |

## 예상 질문

**왜 Recall만 보지 않나?** 불량을 모두 잡아도 정상 제품을 대량으로 불량 판정하면 비용이 커진다. 이번 SECOM 결과가 사례다. Precision과 FPR 제한을 함께 확인한다.

**가장 좋은 모델은 무엇인가?** 이번 분할의 validation에서는 합성 공정 Extra Trees와 합성 이미지 Autoencoder를 선택했다. 데이터·제품·시점·비용 기준에 따라 달라진다. SECOM은 운영 기준을 만족한 모델이 없었다.

**제품을 다 합치면 항상 좋은가?** 가정하지 않는다. 각 학습 조합은 동일한 평가 표본으로 비교한다. 제품 A만 평가할 수도 있다. 현재 합성 공정에서는 ABCD 후보가 선택됐지만 다른 환경의 우월성을 입증하지 않는다.

**데이터가 불균형하면 GAN으로 늘리면 되나?** 이번에는 class weight와 임계값, 정상 전용 이상 탐지를 비교했다. GAN 증강은 구현하지 않았다. 합성 표본이 실제 불량 다양성을 대표하는지 먼저 검증해야 한다.

**LLM이 없는 Agent인가?** ML 학습과 지표 기반 계획·승인·실행을 수행하는 워크플로 Agent다. LangGraph의 역할 분리와 검색은 실제 구현했지만 독립 LLM들이 토론하는 형태는 아니다. 추후 LLM은 자연어 해석·설명을 맡기고 승인 권한은 유지할 수 있다.

**실제 영업이익이 얼마나 늘었나?** 측정하지 않았다. FN·FP 비용 가정의 분류 손실만 계산했다. 현장 파일럿에서 검출·재검사·폐기·처리량을 측정해야 수율과 이익 효과를 검증할 수 있다.

**기업 클라우드에 바로 배포할 수 있나?** Docker/Kubernetes 예시를 준비했다. 현재 로컬 기능을 검증했으며 특정 기업의 인증·DB·승인 정책 연동과 클라우드 배포는 별도 작업이다.
