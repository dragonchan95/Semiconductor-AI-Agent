# 5분 발표와 앱 실행

본문1~12장, 질문용 부록13~17장입니다. 발화 목표260초·화면 전환20초·여유20초로 준비합니다. 실제 리허설 측정값은 아닙니다. [대본](발표대본_G045.txt)을 타이머로 한 번 읽어 발표 속도를 조절합니다.

| 장 | 핵심 | 목표 시간 |
|---|---|---:|
|1|반도체 검사 모델
실험·관리 Agent|10초|
|2|모델을 고를 때와 성능이 떨어졌을 때를 돕습니다|15초|
|3|불량을 놓치지 않되, 정상 오판도 제한합니다|20초|
|4|① 검사 데이터를 선택합니다|10초|
|5|② 비교 범위를 확인하고 승인합니다|20초|

제품 그룹 실험(6장)과 앙상블 실험(7~8장)은 별개 조건입니다. 모델 관리9~10장은 다른 새 배치입니다. 세 수치를 섞지 않습니다. 각 표의 모든 행·모든 기술을 읽지 않고 선택·실패·전후 변화에 집중합니다.

## 발표 중 보이는 흐름

데이터 선택(4) → 계획·전처리 이유·승인(5) → 제품 그룹 선택과Test 실패(6) → 별도 앙상블 비율 선택(7)·Test 확인(8) → 이후 새 배치 점검(9)·승인 재학습 전후 비교(10) → 구조(11)·교훈(12) 순서입니다. 화면 캡처는 실제 실행이고9~10장은 Mac의 새 검증입니다.

새 학습을 발표 중 기다리지 않습니다. 저장된 결과·실제 스크린샷으로 설명합니다. 13장은12개 모델 비교,14장은 공식 문서 RAG,15장은 선택 범위,16장은Judge예시,17장은 점수 없는 기술 대응표입니다.

## 직접 앱 눌러보기

Mac: `start.command` 더블클릭 또는 `bash start.command`. Windows: `start.cmd`. 실행 창을 유지하고 **http://localhost:8700**을 엽니다. 재부팅하면 서버를 다시 켜야 합니다.

1. 제품 A–D 센서 연습을 선택해 완료된 결과를 엽니다.
2. 저장된 제품 그룹·앙상블 결과를 열어 비교합니다.
3. **모델 성능 점검·재학습**을 눌러 새 정답 배치를 점검합니다.
4. **저장된 재학습 결과 보기**가 있으면 바로 전후 비교를 확인합니다. 새 재학습은 계획 검토·승인 후 실행합니다.

현재 Mac·Windows는 로컬 Ollama의 Qwen2.5:1.5b, BGE-M3와 FAISS를 연결합니다. CPU 계획 생성은 수십 초 걸릴 수 있습니다. 새 설치에는 과거 DB·모델 파일이 없으므로 먼저 예제를 준비하고 승인 학습해야 합니다. 공개 원본 기록은 `docs/evaluation/`에 있습니다.
