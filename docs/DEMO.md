# 발표와 앱 실행

본문 1~10장과 질문용 부록 11~16장입니다. 발화280초와 화면 전환20초를 계획했습니다.

Windows에서는 start.cmd를 실행한 뒤 http://localhost:8700을 엽니다. 이 노트북에는 합성 센서 실험 이력이 준비되어 있습니다.
제품 A–D 센서를 선택하고 결과 보기로 확인합니다. 새 비교는 계획 제안 → 계획 검토 → 승인·학습 순서입니다.

결과의 모델별 Validation 비교에서 후보 선택 이유를 확인합니다. 공식 문서에서 비교 후보를 추가하거나 목표를 검토할 수 있습니다. 재학습·기존 모델 점검은 접힌 부가 기능으로 남겨 두고 발표에서 제외합니다.
발표는 저장된 실제 화면을 설명하므로 학습을 새로 기다리지 않아도 됩니다.

현재 Windows는 수업과 같은 Qwen2.5-1.5B 계열을 로컬로 실행합니다. 세 역할의 실제 응답·허용 코드·출처 연결 검사를 확인했고 LangSmith APAC 추적은 별도로 검증했습니다. 모델·코드·근거 조합에 따른 응답 검사 실패는 규칙 설명으로 표시합니다.
노트북 CPU에서 계획 생성에는 수십 초가 걸릴 수 있으므로 발표 때는 준비된 화면을 설명합니다.
기존 Google Slides의 온라인 갱신은 Google Drive 연결 후 확인해야 합니다.
자세한 환경 이동 내용은 HANDOFF_WINDOWS.md를 참조합니다.
