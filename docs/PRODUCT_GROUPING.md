# 어떤 제품 데이터를 함께 학습할까요?

제품별 전용 모델이 항상 더 좋은 것은 아닙니다. 제품별로 나누면 그 제품에 맞는 규칙을 학습하기 쉬울 수 있지만, 학습 데이터와 불량 표본도 줄어듭니다. 제품들이 공통 특성을 가진다면 데이터를 합치는 편이 유리할 수 있습니다. 반대로 제품별 정상 범위와 결함 패턴이 크게 다르면 합친 모델이 불리할 수 있습니다. 어느 쪽이 좋은지는 같은 제품의 같은 평가 행으로 비교해야 합니다.

학습 표본 수와 일반화 성능의 관계는 [scikit-learn 학습곡선 설명](https://scikit-learn.org/stable/modules/learning_curve.html)에서도 확인할 수 있습니다. 여기의 제품별 차이 설명은 실험 설계를 위한 가설이며 특정 반도체 공장의 결과를 뜻하지 않습니다.

## 서로 다른 세 가지 질문

| 질문 | 예시 | 현재 범위 |
|---|---|---|
| 한 모델을 어떤 제품 자료로 학습할까요? | A / AB / BC / ABC / BCD / ABCD | 4개 제품의 비어 있지 않은 학습 부분집합15개 탐색 구현 |
| 공통 모델과 제품 전용 모델 중 무엇이 좋을까요? | ABCD로 학습한 모델 vs A만 학습한 모델, 둘 다 A의 같은 행에서 평가 | 별도 합성 후속 배치에서 실제 비교 구현 |
| 여러 모델의 담당 제품을 어떻게 나눌까요? | 모델1은ABC 담당, 모델2는D 담당 vs 모두 하나 vs 각각4개 | 이런 그룹 구성을 모두 자동 비교·선택하는 기능은 별도 확장 |

AB로 학습한 모델과BC로 학습한 모델을 비교하는 것과, 여러 모델을 배치해 전체 제품을 나누어 담당하게 하는 것은 다른 문제입니다. 현재 임의의 그룹 구성까지 모두 자동 최적화했다고 주장하지 않습니다.

## 보존된 실제 비교

같은 CatBoost 알고리즘으로 전체 제품 공통 모델과 제품별 전용 모델을 학습했습니다. 이 표는 **별도 합성 후속 배치**의 기록이며 본문의90:10 앙상블 실험과 데이터가 다릅니다.

| 평가 제품 | 공통 모델 Validation Recall / 정상 오판률 | 전용 모델 Validation Recall / 정상 오판률 | Validation 선택 |
|---|---:|---:|---|
| A | 98.6% / 14.8% | 94.2% / 14.2% | 공통 |
| B | 89.7% / 13.2% | 89.7% / 14.9% | 공통 참고 · 검출 목표 미달 |
| C | 90.9% / 14.3% | 93.2% / 14.3% | 전용 |
| D | 98.2% / 8.3% | 98.2% / 13.9% | 공통 |

이 사례만 봐도 전용 모델의 우월성은 자명하지 않습니다. 각 행에서 같은 제품의 같은 Validation 행과 정답을 사용했습니다. 다른 제품끼리 Recall을 비교해서 우승자를 정한 것이 아닙니다.
Validation에서 고른 방식이 Test나 미래에 항상 우수한 것은 아닙니다. 예를 들어 C의 전용 모델은 Validation에서 더 좋았지만 보존된 Test에서는 공통 모델보다 검출률이 낮았습니다. Test 확인과 표본 보강이 필요합니다.

## 코드와 발표

- 학습 제품 부분집합: [experiments.cohorts / execute](../app/experiments.py), [기존52조건 실험](evaluation/windows_llm_synthetic.json).
- 제품별 공통·전용 비교: [monitoring.product_plans / compare_strategies](../app/monitoring.py), [실제 기록](evaluation/model_management.json).
- UI에서는 요청과 학습 범위에서 대상 제품과 제품 조합을 설정합니다. 기존 모델 점검을 통한 공통·전용 비교는 접힌 부가 기능에 남아 있습니다. 이번 수정은 이 기능을 제거한 것이 아니라 발표 설명을 복원한 것입니다.
- 발표2·5장에서 학습 제품 범위도 비교한다고 소개하고, 상세 수치는12장 질문용 부록에서 보여 줍니다. 본문 앙상블 사례는 학습 제품ABCD를 고정해 비율 효과를 비교합니다.

ABC와D 같은 그룹 구성을 자동 비교하려면 각 전략이 전체 제품을 중복 없이 담당하도록 정의하고, 같은 제품별 Validation에서 성능·표본·관리할 모델 수를 함께 평가해야 합니다. Test로 그룹을 고르면 안 됩니다.
