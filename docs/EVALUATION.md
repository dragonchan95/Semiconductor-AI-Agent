# 무엇을 평가했나요?

| 구분 | 확인하는 대상 | 구현 |
|---|---|---|
| 분류 성능 | 검사 모델이 실제 불량을 얼마나 찾고 정상을 얼마나 오판하는가 | 정답 라벨과 예측으로 Recall·Precision·F1·FP 계산 |
| Agent 출력 검사 | 허용한 코드와 제공한 근거를 사용했는가 | 코드·출처 연결을 프로그램으로 검사 |
| LLM-as-a-Judge | 결과 설명의 주장이 실제 실험 기록과 맞는가 | 로컬 Qwen을 별도 평가자 역할로 호출 |
| LangSmith | 어떤 역할과 도구가 어떤 순서로 실행됐는가 | root/child 실행 전송·API 재조회 |

결과 검토 Agent는 분류 모델의 실험 결과를 읽고 설명할 사항을 정리합니다.
Judge는 그와 달리 **설명 문장 자체를 평가**합니다. 같은 Qwen을 서로 다른 프롬프트로 호출하므로 별도 학습된 독립 모델은 아닙니다.

## 로컬 Judge 실행

```powershell
..\.venv\Scripts\python.exe -X utf8 scripts/evaluate_judge.py
```

실제 합성 센서 실험의 모델·TP·FP·Recall·목표·적용 범위를 정답 근거로 사용합니다.
올바른 설명 2개와 수치·모델·적용 범위를 변조한 설명 6개를 평가합니다.
각 예제의 사전 라벨과 예제 이름은 평가 LLM에 보내지 않습니다.
LLM이 직접 `supported`를 판정하고, 프로그램은 응답 형식을 검증한 뒤 사전 라벨과 비교합니다.
LLM 호출이나 응답 구조가 실패하면 평가 성공으로 대체하지 않습니다.

최종 실행은 **8개 중 6개에서 사전 라벨과 일치**했습니다.
발견 수를 27개에서 30개로 바꾼 설명과, 목표 미달을 충족이라고 한 설명은 잘못 통과시켰습니다.
초기 실행은 8개 중2개 일치였고 실패 응답1개가 있었습니다. 초기 기록도 삭제하지 않았습니다.

프롬프트를 보완할 때 사용한 작은 **자체 개발 예제**의 결과입니다.
독립 시험셋이나 실제 현장 답변의 일반 정확도를 뜻하지 않습니다.
생성자와 평가자가 같은 모델 계열이라 비슷한 오류를 낼 수 있습니다.
따라서 LLM 평가는 보조적으로 사용하고 정확한 수치 계산·승인·출처 검사는 프로그램에서 유지합니다.
