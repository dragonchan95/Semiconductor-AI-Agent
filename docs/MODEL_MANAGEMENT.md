# 새 정답 배치 기반 모델 성능 관리

목적은 기존 모델이 같은 제품의 새 데이터에서도 불량을 잘 찾는지 점검하고, 필요하면 승인 후 재학습 결과를 비교하는 것입니다. 상시 데이터 감시·자동 양산 배포는 향후 범위입니다.

## 사용 순서

1. 완료된 센서 실험 결과에서 **모델 성능 점검·재학습**을 누릅니다.
2. 센서 열이 같은 독립적인 새 정답 배치를 선택합니다. 변화 합성 데모도 준비되어 있습니다.
3. **기존 모델 그대로 점검**을 누르면 모델·판정값을 고정해 새 Train 구간의 제품별 Recall·정상 오판률·표본을 보여 줍니다.
4. 재학습 제안을 받은 경우 **같은 알고리즘으로 재학습 비교 계획 받기**를 누릅니다. 이때는 계획만 생성합니다.
5. 승인자 이름을 넣고 승인하면 공통·제품별 학습을 실행합니다. 완료 후 같은 제품의 Validation에서 방식을 선택하고 같은 Test에서 결과를 확인합니다.
6. 기존 모델과 같은 알고리즘의 공통 재학습 모델을 같은 새 Test에서 비교합니다. 후보를 저장하며 운영 모델을 자동 교체하지 않습니다.

## 교육용 점검 기준

- 제품별 새 불량20개 이상에서 목표 미달(Recall90%·정상 오판15%) 또는 이전보다 Recall이10%p 넘게 하락하면 재학습 비교를 제안합니다.
- 목표 수치는 원본 실험의 승인 정책을 따르며 90%·15%는 데모 기본값입니다.
- 표본이 부족한 제품이 있으면 유지로 단정하지 않습니다. 다른 제품의 재학습 필요가 확인되면 그 제안을 우선 보여 줍니다.
- 이전 제품별 표본도 작으면 하락 폭은 탐색적입니다. 회사 공통 기준·통계적 드리프트 검정이 아닙니다.
- 정답 없는 입력 변화만으로 Recall 하락을 확정하지 않습니다. 신규 제품은 별도 검증 대상으로 표시합니다.

## 확인한 실행

[Mac 실제 실행 원본](evaluation/lifecycle_mac.json)에 점검·승인자·5개 완료 실행·전후 비교를 저장했습니다. 독립 변화 합성 배치3,840건, Train2,304 / Validation768 / Test768건이며 같은 lot은 분리하지 않았습니다.

| 같은 새 Test | 기존 모델 | 같은 CatBoost 재학습 |
|---|---:|---:|
| 불량 발견 | 43/167 | 153/167 |
| 정상 오판 | 96/601 | 79/601 |
| Recall | 25.7% | 91.6% |

재학습 필요 판단에는 새 Train만 사용했습니다. 재학습 후보와 방식은 Validation으로 고르고 Test는 마지막 확인에 사용했습니다. 과거 데이터의 자동 병합이나 기존 트리에 이어 학습하는 방식은 아닙니다. 단일 합성 배치로 실제 회사 성능·수율 개선을 입증하지는 못합니다.

코드: [monitoring.py](../app/monitoring.py), [API](../app/api.py), [UI](../static/app.js). 13주차 CMP 프로젝트의 점검·승인·재학습 흐름을 참고했으며 회귀 잔차3시그마 기준은 전용하지 않았습니다.
